Reading object dumps

Turn a large object dump into a small, testable integration note.

1. Capture the right context

A loaded-object dump describes the process at a moment, not every cooked asset in the installation. Open the menu or range that owns the feature before searching for its widgets and Blueprint functions. Keep the game/loader version and capture context with your dump.

Use the dump/viewer mechanism supported by your installed UE4SS release. Do not assume a keybind or developer command from another loader build exists locally. The normal loader API documentation is a starting reference, not proof your configuration enabled every utility.

2. Search for a narrow term

rg -n "Attach_POI_C:SetupAttachment" UE4SS_ObjectDump.txt
rg -n "C_CartridgeBase:ChargeMass" UE4SS_ObjectDump.txt
rg -n "Base_BoxMagazine_C:OnSnappedToSlot" UE4SS_ObjectDump.txt

Search the exact class/member once known. A broad word like “modifier” can return engine camera or animation systems unrelated to weapon stats. Read the owning path before deciding a match belongs to the gameplay feature.

3. Read entry type and owner

A class entry names a type; a property entry gives an owner and reflected value type; a function entry identifies a callable integration candidate. Nearby property entries can describe function inputs, outputs, return values and Blueprint-generated local variables.

Do not treat every property listed beneath a function as a public argument. Names such as CallFunc or temporary array indices often belong to Blueprint implementation locals. Compare the actual parameter sequence with a small callback observation.

4. Ignore process addresses for published recipes

Addresses and offsets can help a native debugging session, but copied numbers from an old dump are not portable modding instructions. Prefer exact reflected names and typed APIs. Never use a pointer address as a network entity ID.

A useful published excerpt removes irrelevant process-specific addresses and explains the member’s role. This also keeps a reference page readable instead of turning it into a second enormous raw dump.

A name found in a dump can be documented as a discovery point immediately. A claim that it safely removes a player’s fitted rail requires a different level of evidence. Keep that distinction visible in the hook reference.

Archive and dump disagreement

If an archive browser finds a package but the dump does not, the package may not be loaded. If a menu row names a map that cannot be entered, the reference alone did not prove a working destination. Use Asset paths & loading to test presence, loadability and behaviour in separate stages.
