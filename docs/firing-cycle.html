Following the firing cycle

Trace the trigger, bolt, cartridge and projectile as separate objects instead of replacing the whole chain with a fake shot.

Map the assembly first

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

Start with an assembled weapon in a range. The weapon owns aggregate behaviour, the bolt can carry or chamber a cartridge, and the cartridge participates in ignition and projectile creation. A method name in one class does not tell you all of its preconditions. The purpose of this exercise is to discover ordering while the player operates the gun normally.

Follow the native OnFired and fireBullet declarations through C_CartridgeBase reference. The Blueprint cartridge also declares IgnitePowder and SetChambered. These are investigation points, not a supported public firing API. An arbitrary call can skip ammunition consumption or create an inconsistent assembly.

Record one complete cycle

  1. Record the initial bolt, magazine and chamber observations with ordinary Lua snapshots.
  2. Load using normal controls and record each visible state transition.
  3. Chamber a round, fire one shot and watch which actor identities disappear or appear.
  4. Cycle and eject the case. Confirm whether the chamber reference changes before or after the visual motion.
  5. Repeat without a magazine and then with an empty magazine, using the game to perform the action.
  6. Compare the timelines before proposing a hook or override.

Watch for multiple notifications

A native event may have a Blueprint implementation. A projectile can report more than one impact, and a cartridge may have siblings for a multi-projectile load. Count these separately: trigger attempts, cartridges fired, projectiles spawned, impacts observed and valid target hits. If all five share one counter, scoring and network effects will eventually duplicate or disappear.

Define a successful change

A firing-cycle mod needs more than one working shot. Check the first shot after entering a range, the next shot after ejection, a full reload, an empty-gun attempt, weapon switching and range restart. For a visual-only mod, observe the real firing event and add a cosmetic effect without invoking ignition again.
