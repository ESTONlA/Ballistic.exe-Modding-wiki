Lighting & exposure diagnosis

Use controlled observations to separate invisible geometry from a dark rendering environment.

1. Establish a visible reference

Enter the original working range and record a known object’s appearance, camera location and material. Then create one simple reference object in the runtime scene at a confirmed visible transform. This gives you something to compare besides an entire dark apartment block.

Keep world, material and object placement fixed while changing one lighting-related variable. A different scene location behind an indoor wall is not a fair exposure comparison.

2. Rule out placement and occlusion

Log player position, requested/actual object position and facing. Check whether a wall or enclosing pool geometry blocks the line of sight. Temporarily placing one diagnostic object closer can establish visibility without building a whole map.

A successful spawn log does not guarantee the object is in the view. Conversely, a visible dark silhouette proves some geometry rendered; it does not prove that view distance is the main problem.

3. Compare material response

Try a known cooked material on one diagnostic object and inspect its response. An emissive diagnostic can distinguish a lighting/material issue from total absence, but it is not evidence that the intended lit material now works.

The local custom-range experiments produced dark silhouettes despite geometry appearing. Several light/exposure changes did not yield a finished acceptable scene. That is an unresolved rendering/layout result, not a completed outdoor-lighting recipe.

4. Verify the component you changed

A light actor existing does not prove the intended component was resolved and configured. Check the actual light/skylight component, mobility, world context and relevant property types. A call made against the wrong or unavailable component can leave the scene unchanged.

Likewise, confirm the postprocess volume or camera setting affecting the current view. Reading or setting a property elsewhere in the world does not establish that it contributes to this camera’s final image.

Capture screenshots from comparable positions. When an experiment has no visible effect, record that fact and narrow the cause rather than repeatedly raising unrelated settings.

When to stop calling it a lighting fix

A scene is not finished because an API call returned or one emissive panel became visible. Verify the desired layout, readable targets, player view, material response and return flow. For a true new map, the cooked-content pipeline is a separate requirement. See Plan a runtime range.
