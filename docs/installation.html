Installing UE4SS

Set up the loader, then check the log before adding a mod.

What you need

  • The Windows version of Ballistic.exe.
  • A UE4SS release compatible with your game build.
  • A text editor, such as Visual Studio Code.

The local demo tests used UE4SS 3.0.1 Beta #0, commit 5e627997. This records a tested setup; it is not a recommendation to overwrite a working installation with a different release.

Downloads: UE4SS releases · Experimental builds.

Find the game folder

In Steam, open the game’s settings and choose Manage → Browse local files. From there, open:

Ballistic/Binaries/Win64/

You should see Ballistic-Win64-Shipping.exe. The smaller Ballistic.exe in the game’s top-level folder is a launcher. Install the loader beside the shipping executable.

Install the loader

  1. Close the game.
  2. Extract the chosen UE4SS package beside the shipping executable, preserving the package’s folder layout.
  3. Merge folders carefully if you already have other mods installed.
  4. Launch the game once, then close it and inspect the log.

The setup used for these guides has the following layout. Other loader packages can use a different working directory; follow the installation instructions for your release.

Win64/
├── Ballistic-Win64-Shipping.exe
├── dwmapi.dll
└── ue4ss/
    ├── UE4SS.dll
    ├── UE4SS-settings.ini
    ├── UE4SS.log
    └── Mods/

Check the log

Open ue4ss/UE4SS.log. Look for the loader version and startup messages. The file should have a fresh timestamp from your last launch.

If it is missing or unchanged, check the extraction location and that the files match your loader release. If the game crashes before mods load, resolve the loader setup before adding scripts.

Step-by-step installation check

1. Preserve a working setup

If mods already work, record the current loader version from the log and copy its configuration before replacing anything. Keep the existing Mods directory separate from downloaded loader files. A new loader is not automatically the answer to a broken script.

Use the release archive’s contents as the authority for its layout. Some packages keep UE4SS.dll in a ue4ss subfolder; others use a different root/working-directory arrangement. Do not move individual DLLs into a layout guessed from an unrelated tutorial.

2. Check the executable you are beside

Walk from the Steam install folder through Ballistic → Binaries → Win64. Confirm the filename is Ballistic-Win64-Shipping.exe. If the directory only contains the small top-level launcher, go deeper before extracting.

This distinction matters because a proxy loader must be discovered by the process it is intended to load into. A correctly named file beside the wrong executable can leave you with no loader startup and no useful Lua error.

3. Extract without adding an extra directory

After extraction, inspect the result rather than trusting the extraction dialog. A common mistake is an extra archive-name folder between Win64 and the loader files, or between Mods and the mod itself. Compare your final paths with the package’s instructions.

Do not rename a dependency to “fix” a path problem. Preserve filenames and move back to a known layout if the first launch fails.

4. Do a loader-only launch

Start the game before adding your test script. Wait for a normal menu, exit, and inspect a log with a fresh timestamp. Record the loader’s version and whether startup reached its normal event loop. This creates a baseline for distinguishing an installation problem from a later mod problem.

Observed resultInterpretationNext action
No fresh loader logThe loader may not have started, or you are reading the wrong working directory.Recheck the shipping directory and package layout.
Fresh log, no test-mod prefixThe loader started; your mod discovery or script load still needs checking.Follow the first-mod folder check.
Lua syntax error naming your fileThe script was found but could not compile.Fix the indicated source before engine debugging.
Crash before your script loadsThe first failure is not proof your callback ran.Compare against the loader-only baseline.

5. Add one test mod

Use the minimal first-mod layout, launch again and look for its unique prefix. Keep the loader configuration unchanged during this step. If you change loader version, file layout and script behaviour together, a successful or failed launch is harder to explain.

Upgrading and removing

Close the game before updating. Identify files owned by the loader and files owned by individual mods, then follow the chosen release’s update instructions. Preserve your mod configuration and remove obsolete loader files only when you know they belong to that old installation.

To disable one example mod, remove its enable marker with the game closed. Do not delete shared loader files to disable a single script. Uninstalling a behaviour mod may leave changes already saved by the game, so refit or restore a disposable assembly before testing removal.

For version-specific details, consult the loader installation guide. This wiki’s local setup records are not a compatibility list for every release.
