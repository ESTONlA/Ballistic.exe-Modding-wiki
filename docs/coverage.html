How to read coverage

The README percentage is a rough estimate of game-specific documentation, not a measured fraction of all source code, assets or possible mods. Adding setup pages does not establish that more gameplay systems are fully understood.

The useful measure is whether a guide gives you a reliable entry point, an example and a clear limit. The table below makes those limits visible without treating every topic as complete.

Evidence levels

  • Found in a dump: the name or field existed in the inspected build.
  • Native fixture: an operation ran against actual engine objects in an isolated test.
  • Local gameplay check: the feature was exercised in the game’s menu or range.
  • Real peer check: separate PCs/accounts performed the scenario together.

These levels are different, not interchangeable. A native fixture does not automatically prove a player’s saved assembly or an internet session works.

Known open questions

The exact owned-only attachment rule remains unresolved. A reported rail-removal stat penalty was not reproduced by the recorded synthetic fixture. A visible custom range card did not establish a new map, and runtime-scene lighting experiments did not produce a finished custom range.

The ballistics, ownership and multiplayer guides explain the relevant boundaries in more detail.

Add a finding

Record the game build, loader version, exact object/function and steps you tested. A small reproducible result is more useful than a long list of untested classes. Follow the repository’s CONTRIBUTING.md when opening a documentation PR.

How to add a documented capability

  1. Describe the exact player or modder action the guide is meant to enable.
  2. List the required game objects and loader APIs.
  3. Mark which names are only observed in a dump and which operations were actually exercised.
  4. Provide prerequisites, an example’s required context and an expected observable result.
  5. Include at least one failure case and a way to return to a known state.
  6. Record the game and loader builds that support the result.

A new page can make an existing capability easier to use without expanding the known game API. Conversely, one carefully verified function can add useful coverage even before it warrants a long article. Do not use page count as a substitute for evidence.

How the examples are labelled

Complete files include their required imports and startup wiring. Context fragments explicitly name variables that must already be valid. Pure Lua patterns operate on ordinary tables and values. Illustrative output shows a format and is not presented as a captured run.

The downloadable inspector is educational source adapted from recorded local patterns. Documentation builds, HTML checks and mock tests do not establish that a real engine object or future game build has the same behaviour. The testing guide explains the separate checks.

Research priorities

The largest remaining gaps include complete cartridge construction and ballistics internals, a reliable ownership rule for every attachment, full save schema/migrations, every weapon/target type and a supported custom cooked-content pipeline. New beginner material helps people start, but those gaps need direct investigation rather than longer generic explanations.
