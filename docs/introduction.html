Introduction

A practical guide to modding Ballistic.exe with UE4SS and Lua.

This wiki covers setting up your mod folder, finding game objects, hooking functions and troubleshooting scripts. Start with a small change, check it in-game, and build from there.

You don’t need Unreal Editor for the Lua examples here. UE4SS loads your scripts alongside the game and lets them interact with objects and functions that Unreal exposes at runtime.

Before you start

The examples come from the Windows demo. Game updates can change class names, functions and file layouts. Keep a backup of your saves and check your own build’s log when something behaves differently.

What can you do with Lua?

Lua mods can inspect loaded objects, call reflected functions, respond to game events and create UI using assets the game already contains. Some changes need only a few lines of code.

  • Adjust workshop behaviour and add controls to existing menus.
  • Read weapon or target information for tools and overlays.
  • Spawn and arrange existing assets at runtime.
  • Add keybinds, diagnostics and small quality-of-life changes.

These are starting points, not a guarantee that every game system is accessible. See Custom content for the limits of a Lua-only mod.

A small example

A mod begins with Scripts/main.lua. This is enough to check that the loader is running your file:

print("[MyFirstMod] Hello from Ballistic!\n")

The message appears in ue4ss/UE4SS.log after you launch the game. The first mod guide shows the complete folder structure.
