Modding glossary

A practical vocabulary for reading the guides, logs and reflected game surface.

Use definitions as a starting point

These short definitions explain how the wiki uses common terms. Follow the linked guide for examples, required context and limitations. The same word can have different meanings at different layers: a map container is not a playable map, and a display name is not a network identity.

Actor

A world-owned gameplay object. A visible mesh may be on a component or child actor rather than on the root itself.

Read the related guide →

Component

An object providing part of an actor’s structure or behaviour, such as its visible mesh or physics body.

Read the related guide →

Class

The type used to create or identify instances. It is not interchangeable with a live object of that type.

Read the related guide →

Class default object

The class’s defaults, distinct from the player’s current live instance. Changing defaults is not a targeted edit of one gun.

Read the related guide →

Reflection

The named type/property/function surface exposed by Unreal and consumed by the binding. Not every C++ symbol is exposed.

Read the related guide →

UFunction

A reflected function candidate. Hook availability also depends on loading, signature and the installed binding.

Read the related guide →

Delegate

An event/callback binding concept; not automatically a function supported by RegisterHook.

Read the related guide →

Parameter wrapper

A binding object around callback/container data. Unwrap and copy needed values according to the actual type and lifetime.

Read the related guide →

FName

An Unreal identifier type. Use the representation expected by the target API instead of assuming it is a Lua string.

Read the related guide →

FText

Unreal display/localisation text. Useful for native widget text setters, distinct from a persistent gameplay ID.

Read the related guide →

Soft reference

A deferred content reference, not proof that the referenced class/object is currently loaded.

Read the related guide →

Array

An ordered container. Reflected array binding/index rules must be checked separately from ordinary Lua lists.

Read the related guide →

Set

A typed membership collection. A loaded class and a soft class reference are not automatically equivalent keys.

Read the related guide →

Map container

A key/value collection. Distinct from “map” meaning a playable world/package.

Read the related guide →

World

The current runtime context containing actors. World-relative references and clocks need invalidation on travel.

Read the related guide →

Player controller

Input/pawn/camera-related local context. Not a permanent identity or a substitute for host authority.

Read the related guide →

Pawn

The possessed player actor. A cosmetic proxy model is not automatically this actor.

Read the related guide →

Game instance

Cross-map runtime context holding observed selections/progression fields in the inspected game.

Read the related guide →

Game mode

Authoritative mode context where available. Clients should not assume the host’s mode object is local.

Read the related guide →

Game state

Shared gameplay/roster context; the local roster reads its player-state array.

Read the related guide →

World space

Coordinates in the current world’s frame, distinct from a weapon-local or screen-space value.

Read the related guide →

Local space

Coordinates relative to a chosen root/parent. Correct proxy reconstruction needs a consistent reference transform.

Read the related guide →

Quaternion

A rotation representation with X/Y/Z/W in the observed transform shape, not Pitch/Yaw/Roll copied under new names.

Read the related guide →

Mobility

An engine actor/component setting relevant to allowed runtime movement/assignment; verify the intended component.

Read the related guide →

Collision

Physical/query interaction state, separate from whether an actor is visible.

Read the related guide →

Material instance

A material-derived object used for per-instance parameter choices; parameter existence and slot still need checking.

Read the related guide →

Emissive diagnostic

A way to help prove geometry visibility; not a complete replacement for the intended lit scene.

Read the related guide →

Attenuation

Spatial sound presentation policy, including how a selected cue is heard with distance/context.

Read the related guide →

Attachment POI

A workbench point widget referring to a mount component, current gun and popup list in the observed UI.

Read the related guide →

Weapon template

Selected/persisted assembly data used to reconstruct a live gun; not itself the spawned usable actor.

Read the related guide →

Baseline

A recorded state before the tested operation. It must use the same context/fields as the later comparison.

Read the related guide →

Native fixture

A controlled test using actual engine objects, with narrower scope than all player saves or real network sessions.

Read the related guide →

Authority

The role allowed to decide accepted gameplay state. A display name or received packet does not establish it.

Read the related guide →

Snapshot

A state sample that may supersede an older sample. A save-file snapshot is also not continuous progression merging.

Read the related guide →

Reliable event

A one-time action represented with identity/retry/acknowledgement rules so repeats can be handled safely.

Read the related guide →

Acknowledgement

A bound statement about accepted stream content, not a licence to retire another session’s events.

Read the related guide →

Revision

An identity for changed content such as weapon appearance, separate from a general snapshot sequence.

Read the related guide →

Session/world generation

A boundary that prevents old connection/range messages from being applied to the new context.

Read the related guide →

Interpolation

Rendering between known samples, often at a buffered time. It adds smoothness, not authority.

Read the related guide →

Extrapolation

A bounded estimate beyond the latest sample. It must not move a stale proxy indefinitely.

Read the related guide →

Jitter

Variation in update arrival intervals; different from just average latency.

Read the related guide →

Settling phase

A bounded round phase implementing a documented end-time acceptance policy before the final result.

Read the related guide →

Cooked content

Game-ready packaged Unreal assets, distinct from the developer’s editable source project or an external FBX.

Read the related guide →

Idempotent action

Repeating the request does not duplicate the intended effect, such as one installed button or one accepted hit.

Read the related guide →

Backpressure

A deliberate response when pending work exceeds capacity, rather than unbounded queues or silent loss.

Read the related guide →

When a name is ambiguous

State the actual field, class, API or coordinate/time basis instead of relying on a broad label. “Weapon stats” can mean a per-part modifier, live current aggregate, installed aggregate or displayed UI text. “Connected” can mean invited, transport-linked or gameplay-ready. Precise terms make a bug report reproducible.
