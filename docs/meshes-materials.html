Meshes, materials & textures

Diagnose the mesh, transform, material and texture as separate parts of a visual result.

1. Split the visual problem

A replacement model can be present but too small, reversed, offset, white or incorrectly lit. Treat geometry, coordinate conversion, parent transform, material assignment and texture parameters as separate checks. Fixing one does not establish the rest.

SymptomFirst checks
Wrong way aroundImported basis, local rotation, attachment root.
Too small or offsetUnits, origin, parent scale and relative transform.
White or flat colourMaterial assignment and required texture parameters.
Looks right only when staticPose/root relationship and update path.

2. Prove the mesh independently

Use a known cooked mesh first and inspect its component/transform in a visible place. For procedural geometry, a triangle proves mesh-section calls can produce geometry; it does not prove a whole imported weapon has correct topology, normals, UVs, scale and attachment transforms.

The recorded runtime importer experiments are API/prototype findings. A finished FBX-to-usable-gun pipeline was not validated by them. See Custom content before treating a source model as a ready Unreal asset.

3. Inspect the material slot

Confirm which mesh component and material index are being changed. A weapon can have several components and child actors; setting material zero on the root does not recolour every attachment. Record the original assignment before a reversible preview.

A dynamic material instance lets a feature adjust parameters without editing a shared source material object. The parameter must actually exist under the expected name. A guessed parameter name can do nothing while the instance itself is valid.

4. Check the texture parameter and UVs

A local probe imported a PNG at runtime and created a dynamic material instance from a cooked material with a Tex parameter. That demonstrated the calls and parameter availability in that case, not correct mapping on every model.

If the image loads but the model is white or distorted, inspect the assigned material, texture parameter, UV coordinates and the material’s expected colour/normal roles. A loaded texture object is only one stage in that chain.

5. Compare lit and diagnostic presentation

An emissive material can help establish that geometry is visible, but it removes much of the lighting response you may want in the final scene. Keep that as a diagnostic result. If the final goal is a believable outdoor range, investigate the hosting world’s lighting separately.

Do not compensate for a wrong material with unlimited exposure. Keep a controlled reference object and compare its appearance in the normal range and your runtime placement.

Record a visual verification

  • Mesh identity, component and material slot.
  • Requested and actual transform, including parent/root space.
  • Material instance and parameter names actually found.
  • Texture load result and the expected mapping.
  • Appearance while moving, aiming and changing context.
  • Cleanup/restoration after closing the feature.

This checklist is useful even without a new model: a remote gun proxy can fail any of the same stages while reusing only cooked game meshes.
