Finding game objects

Find an object, check that it is valid, then use it while it still belongs to the current world.

Loaded objects

StaticFindObject looks up an object that is already loaded. It does not automatically load every asset from the game archive.

ExecuteInGameThread(function()
    local object = StaticFindObject(
        "/Game/Data/Weapons/Attachment_Data.Attachment_Data"
    )

    if not object or not object:IsValid() then
        print("[MyFirstMod] Attachment table is not loaded yet.\n")
        return
    end

    print("[MyFirstMod] " .. object:GetFullName() .. "\n")
end

Instances and defaults

A class describes an object type. A class default object contains its default values. A live actor or widget is an instance. Editing a default is not the same as changing the weapon or menu the player is currently using.

Read the full object name and confirm which object you found before writing to it.

World changes

Travelling from the bunker to a range replaces many actors and widgets. A reference that worked before travel can become invalid afterwards.

  • Reacquire world-specific objects after travel.
  • Check validity immediately before use.
  • Clear cached widget references when the menu is destroyed.
  • Keep track of actors your mod spawns so you can clean them up.

Arrays and containers

Unreal containers exposed through UE4SS are not always ordinary Lua tables. In this local loader, using ipairs on some Unreal arrays continued beyond the reported length. A bounded loop worked for those arrays:

local points = editor.POIs
local count = #points
assert(count <= 512, "Unexpected attachment-point count")

for i = 1, count do
    local point = points[i]
    if point and point:IsValid() then
        print(point:GetFullName() .. "\n")
    end
end

This example requires a valid editor instance. Set and map containers have different APIs; don’t apply the array pattern to every container.

Reflected methods

Use methods present in the dump for your build. For actor transforms, the local bindings exposed K2_GetActorLocation and K2_GetActorRotation. Calling an unavailable method produced a TrivialObject error rather than a normal Lua function call.

Walkthrough: find the right instance

1. Identify what kind of name you have

An asset package path, a generated class path, an instance full name and a short class name are different identifiers. For example, a Blueprint-generated class can end in _C; an actor instance can add a runtime suffix. Don’t strip or append suffixes blindly to turn one into another.

2. Establish current-world context

Start with a valid viewport, get its world and use that world to resolve GameplayStatics context. Log the world full name and compare it after travel. A globally loaded class can be reused across worlds; its live actors and widgets cannot be treated the same way.

For a weapon query, decide whether you mean the range pawn’s equipped gun or the workshop’s displayed gun. Both can be valid objects while only one is relevant to the action.

3. Filter candidates deliberately

If a global query returns several editors, inspect validity, visibility, parent/owner and the referenced current weapon. Log candidate names before selecting one. “First valid” is a useful discovery shortcut but a weak production rule if old or hidden widgets remain loaded.

The downloadable inspector reports visible editor candidates explicitly. It doesn’t claim that visibility uniquely proves input focus.

4. Copy values you need later

local raw = actor:K2_GetActorLocation()
local position = {X = raw.X, Y = raw.Y, Z = raw.Z}

-- position is plain Lua data for a comparison or message.
-- Reacquire actor before a later engine operation.

A copied position is not a live binding. It stays unchanged if the actor moves. That makes it useful as a baseline, but you must capture another sample to detect movement.

5. Guard the container and its length

Confirm whether an output is a plain Lua table, a parameter wrapper or an Unreal container. Use a bounded iteration count, handle a missing result, and avoid continuing to use an array whose owner is being rebuilt by the operation you just performed.

A bounded log is useful for discovery. For a production operation, silently truncating a larger array can be a correctness bug; decide whether to reject the operation, continue in batches or report the limit.

Expected result and failure checks

You should be able to name the world, the live instance and why you selected it. After travel, the old cached reference should be discarded and the new instance discovered. If the field is unavailable, check the actual owning class and its reflection signature instead of treating the unavailable value as zero.

If a method call reports TrivialObject, inspect the dump for a reflected alternative. A C++ method name visible in an engine tutorial is not proof that your Lua binding exposes it.
