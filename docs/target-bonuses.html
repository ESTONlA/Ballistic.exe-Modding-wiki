Target bonuses & challenges

Follow target value, challenge assignment and reward state without replacing a scored hit with a cosmetic one.

Identify target and manager roles

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

The target stores per-target state. The target manager maintains collections and assigns bonuses or challenges. A bonus icon is a UI projection of that state, not the source of the score. Start by observing a target that the game already marks with a bonus.

Observe a bonus lifecycle

  1. Record a normal target and a bonus target before shooting.
  2. Copy target ID, type/value, challenge state and the game’s displayed value.
  3. Hit the bonus target once through normal play. Record hit validity separately from reward display.
  4. Try a repeated hit and note whether value reduction or one-hit validity changes the result.
  5. Travel or restart normally and check whether the target actor is replaced and assignments are rebuilt.

Sharing bonuses in a multiplayer mod

Agree on stable target identity within a range epoch. Let the host decide authoritative target/challenge state and reward results, then replicate a bounded cosmetic representation. A guest clicking or shooting a proxy must not award currency locally and again on the host. If bonus state is too large for every update, prioritise changes and send periodic snapshots for recovery.

Check boundaries

  • First and repeated hits produce the same result on both displays.
  • Stance-dependent challenges use the stance at the hit, not the current stance when a delayed packet arrives.
  • Restart clears previous-range IDs and pending bonus events.
  • A visual-only bonus overlay never changes the underlying reward.
