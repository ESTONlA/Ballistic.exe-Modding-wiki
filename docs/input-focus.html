Input, focus & cursors

Make keybinds and menus coexist with game input, cursor state and real button interaction.

1. Confirm which window has focus

UE4SS keybind callbacks in the referenced API require the game or debug console to have focus. A missing response while typing in an external editor does not prove registration failed. Begin with a log-only callback and a unique startup prefix.

Choose a key that does not conflict with another mod or a critical game action. In the teaching examples, F9 or F10 are defaults to change deliberately, not reserved keys guaranteed to be free.

2. Register once and debounce the action you own

local queued = false
RegisterKeyBind(Key.F9, function()
    if queued then return end
    queued = true
    ExecuteInGameThread(function()
        local ok, err = pcall(function()
            -- Your bounded action, with fresh object checks.
        end)
        queued = false
        if not ok then print("[MyMod] " .. tostring(err) .. "\n") end
    end)
end)

This prevents overlapping queued operations, not every possible input-repeat pattern. If you need one action per press or a minimum interval, define and test that rule without hiding legitimate second presses indefinitely.

3. Capture input state before opening your menu

The local panel code remembered the prior mouse-cursor state and used the widget library’s game/UI input modes. On close it restored an appropriate previous mode instead of assuming the cursor should always be hidden.

Do not claim a generic setter name works on every loader/build. Verify the reflected widget/input API you are calling and the owning controller. Menu construction and input ownership need the current world’s context.

4. Keep text entry from firing game actions

When chat or an edit box is active, decide which shortcuts still apply. Sending a message must not also clear attachments or trigger a range action. A global key callback may need your feature’s focus/open-state guard.

Test Enter, Escape, click-outside behaviour and reopening. If an operation closes the menu, restore input state on success and on cancellation/error paths.

5. Distinguish hover polling from native activation

A mouse-hover plus left-button keybind can implement a particular clickable action, as one local workbench control did. It does not automatically provide keyboard/controller activation, focus traversal or accessibility. Copying native styling is not equivalent to binding the native action route.

Use UMG layout to verify hit areas and parent visibility. A button can exist and still be behind another panel or outside the visible bounds.

Input acceptance checklist

  • Key works once when the intended window is focused.
  • Typing in a field does not trigger an unrelated action.
  • The visible hit area matches where the button responds.
  • Escape/close restores the documented input and cursor state.
  • Reopening does not duplicate callbacks.
  • Unsupported input methods are stated rather than assumed.
