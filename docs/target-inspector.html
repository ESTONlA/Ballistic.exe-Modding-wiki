Build a target inspector

Build a read-only target snapshot and use it to distinguish actor state from visible motion.

What you will build

A small single-file mod that logs the current world, target count and a bounded sample of target actor names, hit flags, values and actor positions. It does not call Hit, reset targets, grant score or change saves. Download the Lua source.

This is teaching source adapted from the local discovery pattern. The documentation build checks the source/display relationship; that is not a fresh native-game compatibility test. Use a known range and record the build when checking it yourself.

1. Create a separate mod folder

ue4ss/Mods/TargetSnapshot/
├── enabled.txt
└── Scripts/
    └── main.lua

Copy the downloaded Lua file into Scripts as main.lua and create the empty enable marker beside Scripts. The default key is F10; change it if another mod uses that key. Close and restart the game after editing.

2. Read the complete source

local H = require("UEHelpers")
local MaxTargets = 12
local queued = false

local function valid(object)
    if object == nil then return false end
    local ok, result = pcall(function() return object:IsValid() end)
    return ok and result == true
end

local function unwrap(value)
    if valid(value) then return value end
    local ok, object = pcall(function() return value:get() end)
    if ok and valid(object) then return object end
end

local function snapshot()
    local viewport = H.GetGameViewportClient()
    if not valid(viewport) then return {"Viewport is not ready."} end
    local world = viewport:GetWorld()
    if not valid(world) then return {"World is not ready."} end
    local gameplay = StaticFindObject("/Script/Engine.Default__GameplayStatics")
    local class = LoadAsset("/Game/BlueprintLogic/Targets/TargetBase.TargetBase_C")
    if not valid(gameplay) or not valid(class) then return {"Target discovery API/class unavailable."} end
    local targets = {}
    gameplay:GetAllActorsOfClass(world, class, targets)
    local lines = {"World: " .. world:GetFullName(), "Targets reported: " .. #targets}
    for i = 1, math.min(#targets, MaxTargets) do
        local actor = unwrap(targets[i])
        if actor then
            local position = actor:K2_GetActorLocation()
            lines[#lines + 1] = string.format(
                "%s | hit=%s | value=%s | actor=(%.1f, %.1f, %.1f)",
                actor:GetFullName(), tostring(actor.HasBeenHit), tostring(actor.HitValue),
                position.X, position.Y, position.Z)
        end
    end
    if #targets > MaxTargets then lines[#lines + 1] = "Remaining target lines omitted by MaxTargets." end
    if #targets == 0 then lines[#lines + 1] = "No targets found in this world; try a known range." end
    return lines
end

RegisterKeyBind(Key.F10, function()
    if queued then return end
    queued = true
    ExecuteInGameThread(function()
        local ok, lines = xpcall(snapshot, debug.traceback)
        queued = false
        if not ok then print("[TargetSnapshot] Failed: " .. tostring(lines) .. "\n"); return end
        for _, line in ipairs(lines) do print("[TargetSnapshot] " .. line .. "\n") end
    end)
end)

print("[TargetSnapshot] Teaching example loaded; F10 captures read-only target state.\n")

Read it in this order: validate native references, resolve the current viewport/world, load the target base class on the game thread, discover actors, copy a limited set of ordinary values, then print the completed result. The pending flag prevents overlapping queued snapshots and is released on Lua failure.

MaxTargets bounds printed detail, not the actual game target count. A truncation message is part of the result so a user does not mistake twelve printed entries for twelve targets in the range.

3. Capture a baseline

  • Launch and find the TargetSnapshot startup prefix in the fresh log.
  • Enter a known working range through the normal game flow.
  • Focus the game and press the chosen key once.
  • Record the world name, total reported count and one target you can identify.
  • Keep the raw fields before firing at it.

The output format is a diagnostic record, not a canonical complete target schema. Different subclasses can have additional fields and component behaviour.

4. Compare after a normal hit

Use the normal game action to hit the target, then capture again. Compare HasBeenHit, HitValue and the actor transform. Do not manually reset anything between samples if the question is how the normal action changes state.

If the mesh visibly falls but the actor position barely changes, the next investigation is the body component’s transform. The source intentionally labels its coordinates actor= rather than pretending they describe every visible physics body.

5. Extend one field or component at a time

Inspect the actual target’s components and identify its visible mesh before adding component-position logging. Copy the numeric vector immediately. Keep the selected component’s name/class in the result so another target type is not silently treated as identical.

For a periodic overlay, add the cadence and lifecycle policy from Performance & profiling instead of turning a full actor rediscovery into an every-frame render loop.

Completion check

The useful result is a repeatable baseline/hit comparison with known target identities and a clear scope. It is not proof that all target reset rules, rewards or remote replication are now implemented. Continue with Finding & tracking targets and Hits & scoring.
