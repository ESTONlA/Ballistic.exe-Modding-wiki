Find definition and state objects

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

QuestAsset_C records descriptive quest data such as a name, summary, reward and dialogue references. QuestManager_C owns runtime quest operations. The game instance and save class contain current/completed collections. A definition asset can be present even when a quest has not started in this save.

Trace a quest through normal play

  1. Record the visible quest name and current game-instance/save summaries.
  2. Accept the quest through the normal conversation and note which definition becomes active.
  3. Perform one qualifying action and one non-qualifying action, recording the event context.
  4. Finish the quest normally and distinguish progress completion from the later reward conversation if they are separate.
  5. Reload through the game and compare active/completed summaries without writing a replacement save.

Treat dialogue indices as state

The save and game instance record Shopkeeper_Dialogue_Index and Intendant_Dialogue_Index. Those are not self-explanatory universal conversation IDs. Advancing an index by hand can skip a stage or point at a different list after an update. A dialogue helper should display the current state and observe normal transitions before attempting a change.

Recurring quests and idempotence

The manager exposes recurring-quest token methods as well as ordinary progress. Keep a token observation, an active quest and a completed reward separate in your tool. Reopening a menu or replaying a network message must not repeat a reward. Use an event ID or a confirmed state transition for your own notifications, while leaving the game’s reward transaction to its validated flow.
