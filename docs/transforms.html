Vectors, rotations & spaces

Place objects in the right coordinate space and diagnose wrong scale or orientation.

Start with a coordinate-space label

Epic documents Unreal’s usual world convention as left-handed, Z-up, with X forward and Y right. World, local and screen space are different contexts; importing a model from another tool can require a basis conversion. See coordinate systems and spaces for that convention.

Label every stored transform in your own code: worldPosition, weaponLocalPosition or screenPosition. The label prevents a large class of bugs that otherwise look like a mysterious constant offset.

1. Separate position, rotation and scale

ValueLocal binding shape seen in examples
Location vectorX, Y, Z
RotatorPitch, Yaw, Roll
Transform rotationQuaternion fields X, Y, Z, W
Transform scaleScale3D with X, Y, Z

A quaternion’s W is not a rotator roll. Don’t copy three quaternion components into Pitch/Yaw/Roll or assume imported Euler angles use the same order and units.

2. Calibrate one object

Start with one known cooked mesh and neutral scale. Place it a small safe distance from a known reference and log requested versus actual location. Check its bounds and facing before assembling twenty objects. A mesh’s modelling origin may be far from the part you think of as its centre.

For a weapon preview, distinguish model-space scale from the root actor and parent component transforms. Repeated arbitrary scale changes can hide a wrong parent transform rather than solve it.

3. Capture relative transforms for attachments

A proxy gun should preserve the child mesh’s relationship to the gun root, not copy the original player’s world position. Capture the root transform, transform child world positions into root-local space, then rebuild them against the destination root.

The local proxy code used KismetMathLibrary inverse-transform helpers rather than subtracting world positions alone. Position subtraction ignores root rotation and scale. Verify moving, turning, aiming and switching weapons, not just a single static pose.

4. Interpolate yaw across the wrap

local function yawBetween(a, b, alpha)
    local difference = (b - a + 180) % 360 - 180
    return a + difference * alpha
end

-- The halfway orientation follows the short arc near 180 degrees.
local middle = yawBetween(179, -179, 0.5)

A plain average of 179 and -179 is zero, which points the wrong way for the intended short transition. General 3D rotation interpolation needs the appropriate rotation representation; the yaw example is intentionally limited to a single axis.

5. Validate positions before applying them

Reject non-numeric, NaN, infinite or unreasonably large coordinates in network or imported data. Keep a deliberate bound for the feature’s world scale. A malformed pose should not teleport a proxy to a huge coordinate or enter a physics call.

local function finite(n)
    return type(n) == "number" and n == n and math.abs(n) < 10000000
end
local function positionOK(p)
    return type(p) == "table" and finite(p.X) and finite(p.Y) and finite(p.Z)
end

Diagnose by symptom

A model following the player but facing backwards suggests a basis/orientation issue. A model drifting when the gun turns suggests a space-conversion error. Correct position with wrong size suggests scale/origin assumptions. A successful location setter with nothing visible also requires checking occlusion and the current world. Keep those tests separate.
