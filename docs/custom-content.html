Know which changes can reuse game assets and which need an asset pipeline.

Lua-only mods

Lua is useful for changing behaviour, creating UI and assembling objects from assets already cooked into the game. You can prototype layouts by spawning existing meshes and components in the current world.

That does not create a new cooked map. The scene still belongs to the existing world, with its lighting, streaming and lifecycle.

New models and textures

An external .fbx file is a source model, not a game-ready Unreal asset. A Lua script cannot simply use an FBX path as a normal skeletal mesh reference.

Proper mesh, material and animation integration generally needs compatible cooked assets or a dedicated runtime importer. This wiki does not provide an importer.

Opening the game in Unreal

The installed game contains cooked content, rather than the developer’s editable source project. Installing Unreal Editor does not restore the original Blueprints, levels or source assets.

The local executable reported the UE5.7 release branch. That is useful context when investigating tools, but it does not establish that any specific editor patch will produce compatible content.

Testing a runtime scene

  • Check mesh and material availability in the actual game build.
  • Test lighting and exposure in the world where you spawn objects.
  • Verify collision and a safe player spawn.
  • Keep references to the actors your mod owns.
  • Remove them when the scene closes or the world changes.
