Debugging

Start with the log and a repeatable set of steps.

Read the log

In the layout used here, the loader log is Ballistic/Binaries/Win64/ue4ss/UE4SS.log. Check its timestamp and search for your mod’s prefix.

Log when your script loads, when a hook installs and when the relevant callback runs. Those are three different checks.

local function log(message)
    print("[MyFirstMod] " .. tostring(message) .. "\n")
end

log("Script loaded.")

Common errors

SymptomWhat to check
No log messageMod folder, enabled.txt, script filename and extraction location.
Object is invalidWhether the asset is loaded and whether the world or menu changed.
Hook never runsExact function path, loaded class and whether the game uses that event.
TrivialObject is not callableWhether the method is reflected in this game build.
Freeze while iteratingContainer type, loop bounds and recursive hook calls.
Native access violationThe full crash stack, last callback and recently accessed engine objects.

Handle Lua errors

A protected call can log a Lua failure and stop that operation:

local ok, err = pcall(function()
    -- Run one operation you are investigating here.
end)

if not ok then
    print("[MyFirstMod] " .. tostring(err) .. "\n")
end

pcall does not make an invalid native pointer safe. If the process crashes inside the engine or loader, simplify the callback and inspect the native stack.

Reproduce a problem

  1. Write down the game build, loader version and mod version.
  2. Use a minimal setup with the mods needed for the test.
  3. Record the exact weapon, part or menu involved.
  4. Compare the result before and after the operation.
  5. Restart fully, then repeat the same steps.

For a stat problem, record the value before fitting a part, after fitting it, and after removing it. “It went negative” doesn’t show whether the value dropped below its original baseline.

After a game update

Check function paths and signatures again. Confirm asset availability, menu construction and save behaviour separately. A successful startup log only proves that startup completed.
