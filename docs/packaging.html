Packaging a Lua mod

Make the archive easy to install and leave your development setup out of it.

Pick an archive root

For an archive intended to be extracted into ue4ss/Mods, include the mod folder itself:

MyMod/
├── enabled.txt
└── Scripts/
    ├── main.lua
    ├── config.lua
    └── feature.lua
README.md

Another valid approach is to include the full Ballistic/Binaries/Win64/ue4ss/Mods/MyMod path and instruct the user to extract into the game folder. Choose one root and describe it exactly. Mixing the instructions produces doubled or missing folders.

Include only release files

Use an explicit file list in the build script instead of zipping the whole project. Include the Lua files the mod loads, its enable marker, required mod-owned binaries and the player instructions.

Exclude saves, backup saves, captured screenshots, object dumps, runtime reports, logs, tests, browser profiles and unrelated mods. Don’t package the game or the entire loader with a small Lua mod.

Version the whole mod

Put a version in the startup log and give the archive the same version. A native bridge and its Lua scripts can depend on each other, so ship a complete matching release rather than telling users to update just one file.

If a protocol changes, check the peer’s protocol version before accepting gameplay messages. An application version label alone does not prove wire compatibility.

Write installation instructions

  • Name the loader requirement and tested game build.
  • Show the exact extraction destination and final folder layout.
  • List controls and configuration file locations.
  • Explain the full-restart requirement used by your build.
  • Explain how to disable the mod and what persisted changes remain.

Removing a compatibility script does not necessarily undo an assembly already saved by the game.

Check the archive

Inspect the file list and compare packaged files with the ones you tested. Try extracting into an empty staging folder and reading the instructions as a new user. For an updated release, confirm that renamed or removed modules cannot remain active from the old install.

A checksum can identify the exact artifact you tested; it is not a substitute for testing the artifact’s behaviour.
