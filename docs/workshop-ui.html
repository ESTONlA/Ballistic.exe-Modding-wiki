Workshop UI

Reuse the game’s widgets, but create your own controls and callbacks.

Find the workshop

The observed HUD class is /Game/UI/HUD/Workshop/HUD_Workshop.HUD_Workshop_C. Its attachment editor is WeaponEditMOde, with that exact spelling.

The HUD and attachment editor are related but have different lifetimes. A button placed on the HUD canvas needs its visibility tied to entering and leaving attachment edit mode.

Create a native button

The common TheRangeButton_C class provides the game’s existing button appearance. This creates a separate widget; it does not click or duplicate Save and exit:

local H = require("UEHelpers")

ExecuteInGameThread(function()
    local pc = H.GetPlayerController()
    if not pc or not pc:IsValid() then return end
    local class = LoadAsset("/Game/UI/Common/TheRangeButton.TheRangeButton_C")
    if not class or not class:IsValid() then return end
    local library = StaticFindObject("/Script/UMG.Default__WidgetBlueprintLibrary")
    local button = library:Create(pc, class, pc)
    if not button or not button:IsValid() then return end
    button.Text = FText("My action")
    button.NavText:SetText(FText("My action"))
    -- Add button to your valid parent panel and retain a reference.
end

Place the control

For a CanvasPanel parent, add with AddChildToCanvas and set the resulting CanvasPanelSlot’s anchors, alignment, position and size. Position numbers are relative to the anchors, not always screen pixels from the top left.

A local workbench check found Save and exit at X=50, Y=-50, size 200×40, with bottom-left anchors and bottom alignment. A button directly above it used Y=-100, leaving a ten-unit gap. Those numbers describe that HUD layout, not every resolution or future build.

Don’t copy action delegates

Copy appearance properties deliberately, not the original widget’s action bindings. A copied Save and exit delegate can execute the original action when your new button is pressed.

One local implementation handled the left-mouse keybind and checked the native button’s hover state. That verified a mouse path only; it does not establish controller, keyboard, touch or accessibility support. Prefer a verified button event route when your loader and widget expose one.

Rebuilds and input

Prevent duplicate construction by checking that your widget still has a valid parent. Hide it outside edit mode, cancel pending actions when the displayed weapon changes, and restore any input mode or cursor state you changed.

Test hover, click, closing the menu and opening it again. A widget object existing in memory does not prove that it is visible or clickable.

What was checked

Native button construction, matching canvas layout, duplicate prevention and edit-mode visibility passed local fixtures. Full interaction on every fitted player weapon and input device was not established. The examples describe the local Windows demo setup. See Checking game updates before using them on another build.
