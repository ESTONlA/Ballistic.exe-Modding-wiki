Collision & physics

Keep actor motion, component physics, collision and target scoring as separate states.

1. Identify the moving body

A target’s mesh component can simulate physics while the actor root remains near its original transform. Inspect both before building a motion overlay, reset button or replication scheme. Selecting the first primitive component can return a trigger or collider rather than the visible body.

Use target discovery to record the actual body component and its class. Keep per-class selection explicit when different targets use different structures.

2. Record collision separately from visibility

Hiding an actor does not by itself establish the collision state your mode needs. A broken target may need both hidden and collision changes, while a cosmetic tracer should generally have no gameplay collision at all.

Before a reversible preview modifies a game actor, record its original hidden/collision/tick/physics values. Restore the observed values rather than assuming every actor should finish visible, ticking and simulating physics.

3. Apply impulses only in a controlled action

The local target-effects code used AddImpulseAtLocation on a physics body after validating target state and hit geometry. Its impulse scaling was a mod policy, not a recovered physical formula for every base-game impact.

local function boundedDirection(from, to)
    local x, y, z = to.X-from.X, to.Y-from.Y, to.Z-from.Z
    local length = math.sqrt(x*x+y*y+z*z)
    if length < 0.001 then return nil end
    return {X=x/length, Y=y/length, Z=z/length}
end

A zero-length vector must not be normalised by dividing by zero. Keep the requested magnitude bounded and explain its units/policy rather than sending arbitrary peer-supplied impulse values to the engine.

4. Treat player recovery as another operation

Moving a stuck player back to spawn is not the same action as resetting a target mesh. The local recovery path stopped movement, used a recorded spawn transform, checked teleport success and requested a net update under host authority.

A failed teleport because the destination is obstructed should produce a recovery message or range-restart option. Repeating it invisibly every tick does not make the spawn safe.

5. Test reset on several body states

Try an upright target, a fallen physics target, an already-hit one-shot target and a broken/hidden target. A successful transform assignment on one does not recover all of the others. Some classes can carry additional state beyond the flags you have observed.

When a complete reset is not understood, expose a clearly defined range restart rather than a partial reset labelled as universal. Keep score reset and physical restoration as separate mode decisions.

Networked motion

Apply authoritative target state and render motion without re-triggering rewards. For physics bodies, decide whether remote clients simulate or follow snapshots; two competing simulations can diverge. Restore borrowed body state when leaving the feature and discard old-world references after travel.
