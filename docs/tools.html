Game inspection

Start with the UE4SS object viewer and object dump to inspect what the current game session has loaded. Use an archive browser when you need to look for cooked content that isn’t loaded yet.

  • FModel — Unreal archive browser.
  • FModel getting started — configuration and usage.

Tool support depends on the game’s engine and archive format. Finding an asset in an archive does not guarantee it can be loaded in every game mode.

A practical discovery session

  1. Pick one behaviour and reproduce it normally in the game.
  2. Locate the relevant class/function in the loaded object view.
  3. Copy the exact path and parameter types into a small research note.
  4. Install a read-only logging hook after the class is loaded.
  5. Trigger the normal behaviour and compare callback arguments.
  6. Only then prototype a change using a disposable context.

Archive inspection and object inspection answer different questions. Keep both results when they disagree instead of assuming one tool is wrong: the asset may exist without being loaded, or a reference may point at content unavailable in this build.

Version drift in documentation

The development UE4SS docs can describe features newer than the local loader. Prefer a small known API surface when writing a portable example, and check the installed version before adopting a new delayed-action or mod-management API.

Keep links to the primary references with your notes. A copied snippet without its API version and required context is harder to maintain than a short explained example.
