UMG panels & layout

Choose the panel and slot that match your layout instead of treating every position as a screen pixel.

1. Identify the widget tree and parent

A UMG control belongs to a widget tree and is attached to a parent panel. The parent decides its slot type. A canvas, vertical list, horizontal row and wrap box do not interpret layout properties the same way.

PanelLayout role
CanvasPanelAnchored/aligned placement with a CanvasPanelSlot.
VerticalBox / HorizontalBoxOrdered children along one axis.
WrapBoxChildren wrap into rows according to available space.
SizeBoxExplicit width/height constraints around a child.
BorderBackground/padding around content.

2. Configure the slot produced by that panel

AddChildToCanvas returns the canvas slot used for anchors, alignment, position and size. A list panel instead supplies its own padding/size rules. A SetPadding method seen on one slot is not proof every slot class exposes it.

Inspect the original game widget’s parent and slot when matching an existing control. Copy the supported appearance/layout values deliberately; do not copy its action delegates.

3. Reason about anchors and alignment

Anchors define the reference area; alignment defines which point of the child is placed at the resulting coordinate. With bottom-left anchoring and bottom alignment, negative Y can place a button above the bottom edge. Changing only position without matching those values often works at one size and breaks at another.

Use the tested Save and exit layout in Workshop UI as a build-specific example, not a universal coordinate set for every HUD.

4. Choose visibility intentionally

Visible, collapsed, hidden and hit-test-related states have different consequences. Use the actual enum/value mapping verified for your binding. The local controls used visible/collapsed transitions when entering/leaving edit mode; those actions also affected whether a layout reserved space.

A non-interactive decorative overlay should not intercept the player’s mouse just because it is visible. Conversely, a hidden/collapsed parent can make a valid child widget impossible to interact with.

5. Check text, wrapping and colour types

Use FText where the setter expects display text. Check long labels and translated/Unicode names, not only a short English placeholder. A fixed-width button can clip or stretch the whole row unexpectedly.

UMG brush/linear colours and TextRender byte colours are not interchangeable shapes/ranges. The local code used float linear colour values for panels and byte-like values for nameplate text. Match the setter’s reflected type.

6. Test rebuilds and scrolling

Open the menu, change the selected attachment, resize and reopen. Confirm the control remains inside the visible panel and is not recreated twice. For long settings, use a deliberate scroll layout rather than extending content beyond the black menu bounds.

For a new panel, prove appearance, focus and action separately. A correctly sized button that still invokes Save and exit has failed even if it looks native.
