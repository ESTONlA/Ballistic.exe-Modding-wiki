Weapon audio & spatial sound

Reuse verified cooked cues and separate remote cosmetic sound from local weapon simulation.

1. Inventory actual sound assets

The local code used cooked shot cues under /Game/SFX/Cues/Shots and handling cues under /Game/SFX/Cues/Manipulation/Generic. Native checks resolved the selected sound assets and exercised spatial playback calls. That does not establish the exact acoustic result for every gun and distance.

2. Load and validate before playing

Load on the game thread and confirm SoundBase compatibility in the tested binding. Keep a bounded allowlist of supported cue identifiers. A network peer should choose an ID from that list, not an arbitrary path to load.

local sound = LoadAsset("/Game/SFX/Cues/Shots/Shot_9mm.Shot_9mm")
local base = StaticFindObject("/Script/Engine.SoundBase")
if not sound or not sound:IsValid() or not base or not base:IsValid()
    or not sound:IsA(base) then return end

3. Use the right source position

For a remote shot, use its captured muzzle/weapon position rather than the listener’s camera position. For a UI confirmation, world spatialisation may not be the intended presentation. Keep sound policy tied to the event type.

The local implementation passed a known shot attenuation asset to PlaySoundAtLocation. Inspect the reflected signature for your build before copying a long parameter list. A valid cue with inappropriate attenuation can sound wrong even though the function call succeeds.

4. Document classification as a heuristic

The local selector used cartridge/weapon names, suppressor-related information and black-powder state to choose among a small cue list. That is a practical cosmetic mapping, not proof that it reproduces every weapon’s true base-game sound selection.

If the cue mapping is unknown, use a deliberate fallback and keep the diagnostic visible. Do not fabricate a precise per-calibre audio claim from one matching substring.

5. Avoid duplicate playback

The firing player already hears the normal local weapon sound. A remote cosmetic event should not blindly play it again on the sender. Retransmitted reliable events also need deduplication so one shot does not produce several echoes from repeated packets.

Reload sounds should follow actual magazine/handling events rather than an assumed fixed animation timer where possible. Empty, cancelled or different reload paths can have different event sequences.

Listening test matrix

  • Local shot without remote replay remains unchanged.
  • Remote shot plays once at the remote source position.
  • Distance and attenuation behave acceptably.
  • Suppressed/black-powder/fallback choices are documented.
  • Magazine release/insertion are not confused.
  • Mute/volume settings and travel cleanup work.

Use actual listening checks in addition to asset-resolution logs. For network events, see Messages & reliable events.
