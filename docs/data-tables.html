Reading data tables

Find the table, inspect a row, and keep discovery separate from mutation.

Find a table

The demo has tables for attachment mount definitions and range menu data. You can inspect them once the asset is loaded:

ExecuteInGameThread(function()
    local data = LoadAsset("/Game/Data/Ranges/RangeData.RangeData")
    if not data or not data:IsValid() then return end

    local names = data:GetRowNames()
    for i = 1, #names do
        print("[MyMod] Range row: " .. tostring(names[i]) .. "\n")
    end
end

Read a row

In the tested loader, FindRow accepted a Lua string as the row name. Passing an FName in that particular call returned no row. This is different from APIs that explicitly expect an FName.

local row = data:FindRow("PistolRange")
if row then
    local map = row.MapName_3_02B8F3864CDF2B67468FDD80A1766519
    print("[MyMod] Map: " .. map:ToString() .. "\n")
end

The long suffix belongs to a Blueprint struct field. Copy the field name from your build’s dump instead of shortening it to MapName and assuming that will work.

The attachment table contained 86 mount rows in the inspected build. That is a build observation, not a constant your mod should require forever.

Watch the field types

A row can contain names, text, class references and soft class references. A soft reference is not the same thing as a loaded class. Converting, loading or iterating them can trigger additional engine work.

Keep an initial probe small: list names, read one known row, then inspect one field. Don’t start by copying the entire table into Lua.

Before changing data

Changing a row affects every consumer that reads the live table. Rewriting recursive mount relationships can also introduce cycles. A previous broad attachment-row copying experiment froze the game; a targeted lookup hook was used instead.

Make any edits reversible, preserve original values and test teardown. Adding a menu row doesn’t create its map or asset. See Range menus & travel.

What was checked

Row-name listing and string FindRow calls were exercised locally. Broad soft-reference copying is a known failed experiment, not a recommended technique. The examples describe the local Windows demo setup. See Checking game updates before using them on another build.
