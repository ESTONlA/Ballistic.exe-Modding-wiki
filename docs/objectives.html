Weapon objectives & hit sequences

Inspect weapon objectives and the hit sequence they evaluate before building progress displays or challenge extensions.

Keep objectives separate from rewards

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

The native objectives manager declares an objective collection and a hit sequence. The Blueprint manager adds gameplay-facing methods. A completed objective, an awarded quest and an updated wallet are separate state transitions. Observe each rather than calling every promising completion method at once.

Build a read-only progress observer

  1. Choose one visible objective and write down its text exactly.
  2. Record the relevant manager and target-weapon reference before the first shot.
  3. Perform a short sequence that should not complete the objective, then compare recorded sequence length and visible progress.
  4. Perform the required action normally and record which evaluation/completion events appear.
  5. Repeat after switching weapons to see whether history is per weapon, per session or filtered at evaluation.
  6. Use copied scalar summaries in the HUD rather than holding a live container element across updates.

Do not silently reorder history

An objective may care about consecutive hits, any qualifying hits, a stance, a scope/laser flag or a specific target context. Sorting the history for display can destroy those relationships if you then feed it back into the game. Keep an immutable observation order and derive a separate presentation list. The presence of an unordered filtering function is not evidence that all objectives ignore order.

Check a progress display

  • The observer can explain both an accepted hit and a non-qualifying hit.
  • Reopening the workshop does not add duplicate sequence entries.
  • Switching weapons refreshes the target context.
  • No observer function grants currency or marks an objective complete.
