Energy, surfaces & impact behaviour

Investigate what happens at an impact without treating a surface enum or a remaining-energy value as a complete penetration model.

Separate the observations

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

An impact location, a registered target hit, a ricochet, a material sound and a projectile disappearing are different observations. Begin with a read-only timeline and a single controlled surface. A coloured impact marker demonstrates a cosmetic effect; it does not prove that penetration was simulated or shared with another player.

Resolve physical surface identity

Unreal physical surfaces are project-defined mappings. A numeric SurfaceType value cannot be labelled steel or concrete from a generic enum name alone. Record the physical material or the game’s own target-surface field when available, then compare known surfaces in the current map. Collision geometry and a mesh’s visible material need not be the same thing.

See Epic’s physical-material guide for the engine concept. It is background documentation, not the mapping for this game build.

Build an impact comparison

  1. Choose one gun, one ammunition configuration and a reproducible firing position.
  2. Fire at the same surface from several angles while recording all impacts, not only scored hits.
  3. Capture the projectile identity, surface observation and velocity before/after only if the hook phase actually exposes them safely.
  4. Track whether the same projectile produces a later impact. Do not infer continuation merely from two nearby markers.
  5. Repeat on a second known surface and compare the event order before proposing a material-specific rule.

Copy impact data before deferring

Hit-result wrappers may refer to callback-owned memory. Copy only the coordinates, plain enum values and other required scalar data while the callback is valid. Keep raw engine wrappers out of delayed tables. If a projectile has been destroyed by the time a UI timer runs, the marker should still be able to display its copied event data without asking the dead actor for its position.

What a useful result looks like

  • A labelled surface mapping supported by controlled shots.
  • A timeline that distinguishes one continued projectile from separate projectiles.
  • A cosmetic marker tool that leaves damage and scoring unchanged.
  • A documented hook phase and an explicit list of copied fields.
