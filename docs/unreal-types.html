Names, text & soft references

Choose the right representation for names, display text, classes and references.

Names and display text are different

A Lua string is ordinary script text. Unreal also has FString, FName and FText. Epic describes FName as an identifier type and FText as the user-facing/localisation text type. Those purposes do not mean every binding accepts either one automatically. See Epic’s string-handling reference.

ValueTypical use in these guides
Lua stringLogging, configuration and the tested FindRow argument.
FNameRow/identifier values where the engine signature expects a name.

1. Follow the called API’s signature

The local range-table test used FindRow("PistolRange"). Passing an FName to that particular binding did not return the row. Other APIs in the same game do expect FName. The correct conclusion is to match each API, not to replace every name with a string everywhere.

-- Each line illustrates a different destination type.
local row = data:FindRow("PistolRange")
local id = FName("PistolRange")
label:SetText(FText("My range"))

Keep reflected member spellings exact, including generated suffixes. FName’s comparison behaviour does not justify changing filenames, Blueprint property spellings or authored asset paths arbitrarily.

2. Convert only for the purpose you need

Convert a name/text value to a Lua-readable string for logging or a copied UI snapshot. That does not preserve every localisation or identity property of the original object. Don’t use a translated display label as the persistent ID for a target or part.

If an object lookup expects a class path, keep that path in a distinct field from its display name. A stable internal ID and a user-facing label can change independently; a language switch should not change gameplay identity.

3. Treat soft references as a separate type

A stored soft reference is not necessarily an already loaded UObject. Inspect its type and the supported conversion/load path. An ownership set storing soft class references cannot safely be treated as a set of arbitrary loaded UClass values.

The local ownership experiment crashed after using the wrong representation in a native set check. A later isolated conversion probe established one safe call, not a complete ownership solution. Use Ownership & unlocks for the full investigation and its remaining limits.

4. Copy small struct values explicitly

Positions, rotations and colours are structs with named fields in these bindings. Copy the fields you need into ordinary Lua data for later comparison. Don’t assume that retaining a borrowed wrapper makes it independent of the native owner or callback lifetime.

local raw = actor:K2_GetActorLocation()
local saved = {X = raw.X, Y = raw.Y, Z = raw.Z}
-- saved is a snapshot, not a live engine reference.

Troubleshooting type mismatches

  • Write down the stored type and the function’s expected type.
  • Inspect the original path before normalising it.
  • Distinguish unavailable from a real nil/false/zero value.
  • Test a single known positive and negative case before a whole catalog.
  • Do not use pcall as a claim of native memory safety.

Use Arrays, sets & maps for container-specific handling and Reading data tables for generated row fields.
