Troubleshooting FAQ

Work through common failures by identifying the first layer that is actually broken.

Why is there no startup message?

Check a fresh loader log, then the actual installed folder, enabled marker, file extensions and script path. A source project and a ZIP existing on disk do not mean the loader is running either. Add a unique version prefix and follow Your first mod.

The mod loads, but the key does nothing

Focus the game, verify the configured key and remove duplicate/conflicting registrations in the test setup. Start with a log-only callback. If that works, the input registration is not the first broken layer; inspect object context and the scheduled action next. See Input and focus.

Can I use Roblox Luau code?

The examples target UE4SS Lua and its APIs. Roblox services, Instance APIs and Luau-only syntax are not supplied by the game. Translate the actual language/API assumptions rather than changing the extension on a Roblox script. Begin with Lua basics.

Why does a method say TrivialObject is not callable?

Confirm the member is a reflected function exposed by this build. A familiar C++ name is not proof it is available through this binding. Inspect the dump for the actual K2/reflected method and verify the owning instance before calling it. See Reflection.

Why is a reference nil after it worked before?

A menu rebuild, weapon switch or travel can replace the native owner. Reacquire world-specific references and cancel pending jobs with the old context. A Lua variable retaining a wrapper does not guarantee the native object remained valid. See Timers and cleanup.

Why did an array loop freeze?

Check whether it is a reflected Unreal container rather than a plain Lua table, and whether iteration can exceed the reported count. Also check callback recursion. The recorded wrapper issue was avoided with a bounded numeric loop; do not apply ipairs blindly to every engine container. See Arrays, sets and maps.

Removing a grip makes the stat negative—is that a bug?

Compare the same field/context before fitting, while fitted and after removal. A negative baseline returning to itself is different from an accumulated penalty. Repeating the exact rail/part case and checking the editor/live/save lifetimes is essential. The recorded synthetic test did not reproduce the player’s alleged residue. See Weapon stats.

Why are known owned parts missing?

Purchased, default, fitted, unlocked and visible are not the same states. Verify the stored reference type and a small set of named positive/negative examples against the real menu. Earlier save-index filters were not a completed reliable ownership API. See Ownership and unlocks.

The custom range card works, but it opens the pool

The card’s title/layout and the destination are separate. Check the actual map ID/package selected and the loaded world after travel. A new UI row does not create a new cooked map; a runtime scene can still be hosted by the pool world. See Range menus and travel.

The scene spawned but is almost black

Keep a known object/material fixed and inspect placement, occlusion and the actual light/postprocess components affecting the view. Visible dark silhouettes are not proof of a view-distance failure. An emissive diagnostic is not a finished outdoor lighting solution. Use Lighting diagnosis.

Can a Lua script use my FBX as a normal weapon mesh?

An FBX source file is not a cooked Unreal mesh/class. The local procedural/texture probes did not establish a finished usable weapon import pipeline. Decide whether you need a runtime preview or proper asset integration and document that scope. See Custom content.

Both players arrive, but a gun is missing

Check the local usable gun, selected template and remote cosmetic proxy separately. Travel can require reacquiring the pawn and rebuilding loadout/visual state. A friend’s visible model is not proof the local inventory weapon exists, and vice versa. See Weapon assemblies.

Does Steam automatically synchronise every target and score?

No. Identity, session and transport are separate from your gameplay protocol. Choose authority, event identity, target state and interruption rules, then test them on both peers. A successful invite or connection is only the first milestone. See Steam sessions.

Does relaying mean there cannot be lag?

Transport does not eliminate latency, jitter, loss or application mistakes. Observe the actual session and keep movement interpolation, reliable events and score timing as separate concerns. Don’t promise a particular route or performance from an invite screenshot. See Movement interpolation.

Why are hits or chat displayed twice?

Look for duplicate callback registration, base/derived handling of the same event, resend without deduplication, or a local cosmetic event replaying on its sender. Track event ID, session/round context and accepted acknowledgement. See Reliable events.

Does sharing the host save merge progression?

A one-way persisted snapshot does not merge simultaneous progress or replicate future unsaved changes. Receiving and applying must be separate actions with a verified backup/reload path. See Reading and backing up saves.

A local test passed—can I claim full compatibility?

State exactly which test passed. Language/mocks, native fixtures, real menu use, save/reload and independent real peers establish different things. A narrow result is still useful; expanding the claim without another test is not. See Test a mod step by step.

Does this wiki now cover the whole game?

It covers a broad practical modding surface, with explicit gaps in areas such as complete ballistic internals, universal ownership rules, full save schema and cooked-content support. Page count is not a measured fraction of the game. The coverage page records those limits and evidence levels.
