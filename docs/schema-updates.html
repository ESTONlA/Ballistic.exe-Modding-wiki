Tracking schema changes

Compare reflected declarations between builds before changing mod code based on a missing field.

Keep the source snapshot identifiable

The bundled game API is imported from a local object-dump file dated 10 October 2026. Its game-build provenance was not recorded. The source hash identifies that file, but cannot tell you which Steam update produced it. Record the current build and loader alongside every new dump rather than treating the import date as the capture date.

Compare schema, not memory layout

  1. Keep the old metadata and capture a new dump in the game state you need to investigate.
  2. Record map, loaded menus, Steam build and loader version; a loaded-object dump only sees what was present.
  3. Compare exact class paths, parent classes, declared fields/types and function names.
  4. Separate a truly removed declaration from one missing because its asset was not loaded.
  5. Inspect changed native/Blueprint ownership: a method may move into a parent without disappearing from the live object.
  6. Run a narrow runtime check for the operation your mod uses before shipping a compatibility change.

Use the offline API query

node tools/query-game-api.mjs ScopeBase_C
node tools/query-game-api.mjs CurrentEnergyInJoules --kind function
node tools/query-game-api.mjs PurchasedParts --kind field --limit 10

These commands read the bundled metadata. They do not attach to the game, load an asset or validate whether the old path remains available in your current session. The query result includes the declaring owner and a wiki reference link.

Common false differences

DifferenceCheck before calling it a breaking change
A widget is missingWas the corresponding menu open or its class loaded?
Field count changedDid the parser preserve spaces and avoid treating function locals as class fields?
Memory address changedExpected between processes; addresses are not stable IDs.
Type name changedDid an object reference become soft, or did only display formatting change?
No new fields on a child classCheck inherited declarations on the parent.

Import deliberately

The importer takes an explicit local dump path and writes a portable metadata file without runtime addresses or offsets. Review the diff before rebuilding reference pages. The generated catalog is not a patch plan: a removed field needs a new observation path or a gracefully disabled feature, not a hardcoded replacement offset.

Document the compatibility result

Write the exact operation tested, the build it ran on and what happened. A successful loader startup does not validate every weapon, menu or save path. Keep known failures in a separate note and avoid calling a schema-only comparison a gameplay regression pass.

Continue with game update checks, dump capture and reading, layered test evidence.
