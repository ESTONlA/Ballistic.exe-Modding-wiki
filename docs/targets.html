Finding & tracking targets

Find the range’s target actors, then inspect the component that actually moves.

Discover targets

The inspected range uses TargetBase_C and derived classes. Get the active world from the viewport, then query that world:

local H = require("UEHelpers")

ExecuteInGameThread(function()
    local viewport = H.GetGameViewportClient()
    if not viewport or not viewport:IsValid() then return end
    local world = viewport:GetWorld()
    if not world or not world:IsValid() then return end

    local class = LoadAsset(
        "/Game/BlueprintLogic/Targets/TargetBase.TargetBase_C"
    )
    if not class or not class:IsValid() then return end
    local gameplay = StaticFindObject("/Script/Engine.Default__GameplayStatics")
    local targets = {}
    gameplay:GetAllActorsOfClass(world, class, targets)
    print("[MyMod] Targets found: " .. #targets .. "\n")
end

Actor versus component motion

A physics mesh can move while its owning actor’s transform stays unchanged. Capturing only K2_GetActorLocation can therefore show a target standing upright remotely while its mesh has fallen over locally.

Inspect the primitive, static-mesh or skeletal-mesh component that carries the visible body. Capture its world transform separately. Different target classes can need different component selection.

Sampling and caching

Discover actors infrequently and sample known targets on a bounded budget. Give moving and recently hit targets priority. A local registry once contained hundreds of targets; rediscovering or loading assets for every target on every frame is unnecessary.

Invalidate the registry after travel. Runtime addresses identify local objects only; they are not stable network IDs.

Resetting targets

Clearing HasBeenHit alone does not restore a broken target, a displaced physics body, its collision, or a reduced score value. A complete reset needs the original state of each relevant field and component. Restarting the range can be a more reliable first reset implementation.

What was checked

Local discovery, target baselines, distinct synthetic targets and actor/component motion were tested. The documented registry strategy is a mod implementation, not a built-in replication service.
