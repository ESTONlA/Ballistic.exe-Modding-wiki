Graphics settings & visual diagnosis

Diagnose a visual problem by separating missing geometry, missing effects, lighting and postprocessing.

Start with a working control

Before changing global rendering settings, check whether the original game effect is visible in the same scene. A synthetic laser rig failed to show the baseline laser and a separate control decal; its parameter-readback success did not establish a visible colour change. That is a failed visual fixture, not evidence that a larger exposure value is the correct fix.

Work through the rendering stages

QuestionEvidence to capture
Did the actor/component exist?Exact current object name, owning world and validity.
Was geometry assigned and visible?Mesh reference, visibility state, transform and bounds.
Was the material assigned?Actual material object on the correct slot/component.
Did a parameter change?Readback from the actual dynamic instance.
Did the effect reach the frame?A screenshot with a working unmodified control.
Did postprocessing change perception?Comparison using the game’s normal scene and view mode.

Separate display settings from gameplay

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

FieldRecorded typeUse in the investigation
DynamicFramerateBoolA persisted setting candidate, not a general render-distance variable.
DynamicFramerateTargetIntA target setting whose runtime counterpart uses Eco naming.
ShowCartridgesBoolA recorded presentation-related option.
VeryLoudShotsBoolAudio-related setting; unrelated to draw distance or exposure.

A field that contains the word dynamic is not automatically a streaming or distance control. Record what the game’s own options menu changes before linking a saved value to a render console command.

Change one variable at a time

  1. Capture the unmodified scene, camera position, resolution and relevant game settings.
  2. Reproduce the missing effect with one known actor or component.
  3. Check transform, visibility, material and normal game ownership before changing exposure or scalability.
  4. If a temporary console diagnostic is necessary, run it only in a private test process and record the original value.
  5. Compare against a control effect, then return to normal settings and test the mod again.

Distance is only one possible cause

Bounds, culling, visibility, decal fade thresholds, a wrong material slot, missing capture output or a world mismatch can all look like a distance problem. Moving a test object closer is a useful controlled experiment, but permanently disabling culling does not explain the cause. Large runtime scenes also need collision, a ground surface and coherent lighting; spawning hundreds of cubes does not recreate a cooked level’s environment.

Write a reproducible visual report

  • Include baseline and changed images from the same viewpoint.
  • Name the exact material/component and show the numeric readback separately.
  • State whether the test used the normal range or a synthetic scene.
  • List temporary renderer commands without shipping them as unexplained global overrides.
  • Report a visual limit honestly when the control itself is invisible.
