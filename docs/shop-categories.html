Shop listings & purchase state

Separate what the shop lists, what it allows you to buy and what the player already owns.

Three different questions

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

An attachment may exist in an asset archive, appear in a shop category and still not be purchased in the current save. A current weapon can also contain a part whose acquisition history is not obvious from one collection. Keep asset existence, shop availability and ownership as separate observations. Earlier owned-only filtering work did not establish a universal rule for every attachment.

Trace a single normal purchase

  1. Choose one inexpensive item that the current save has not already bought; keep a separate save backup using the game’s ordinary file workflow.
  2. Record the item’s exact class path, display name, category and initial purchase/availability state.
  3. Select it normally and observe the preview without buying.
  4. Buy through the game once, then compare wallet, purchase collection and the widget state.
  5. Close/reopen the shop and reload normally to check persistence. Do not replay a purchase callback to make the menu refresh.

Normalise identity without losing information

Display names can be localised or repeated. Soft class references, loaded UClass objects and live part actors represent different stages of the same content identity. Your diagnostic can record a canonical path string next to each original representation, but conversion must preserve enough detail to distinguish variants. Do not cast one Unreal container into another by assigning a Lua table.

Build an explainable list

If a filter hides an item, log the exact reason: not in the observed purchase set, not currently available, wrong category or unresolved reference. Show unresolved ownership as unknown during development rather than silently pretending the part is locked. This makes reports about missing lasers or quest rewards reproducible instead of turning every discrepancy into another guessed exclusion.
