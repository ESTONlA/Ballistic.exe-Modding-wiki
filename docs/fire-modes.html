Triggers, safeties & fire modes

Separate trigger intent, safety restrictions and the weapon’s firing mode before changing input behaviour.

Locate the setting and its owner

The names below are recorded in the local object snapshot dated 10 October 2026. That snapshot does not identify its game build. Resolve the same names in your current build before using them; the investigation steps below are not a report that every operation was tested.

The enum reference contains EFiringModes and EWeaponFailureTypes. The presence of an enum does not mean every weapon supports every value. Start from a gun that already exposes the intended selector. Capture its current configuration, then use normal controls to find the object whose state actually changes.

Trace one player action

  1. Record one press, one release and the resulting fired-cartridge count.
  2. Hold the trigger long enough to distinguish a repeated input callback from actual automatic fire.
  3. Move the selector normally and repeat with the same ammunition and weapon assembly.
  4. Observe the safety restriction through the failure notification rather than assuming it lives on the same component as the trigger.
  5. Change stance, enter manipulation mode and open a menu; check whether input is suppressed in each state.

Do not build a frame-rate fire timer

An input event reports intent. The weapon mechanism decides whether a shot can happen. A mod that calls a firing function on every rendered frame changes its rate with performance and may bypass cycling or ignition. If you are designing a separate challenge overlay, count observed shots. If you are changing a real weapon, find the validated mechanism and its timing constraints first.

-- Pure Lua: keep a cosmetic button state separate from shot observations.
local input = {held = false, presses = 0}
local function pressed()
    if not input.held then input.presses = input.presses + 1 end
    input.held = true
end
local function released() input.held = false end
-- These functions do not fire, chamber or consume anything.

Use the game clock consistently. Do not use os.time for sub-second rate measurements; it is too coarse for that job. Your loader and chosen engine timer have their own precision and pause behaviour, so record those assumptions.

Label controls honestly

A mode selector should only offer modes that the current weapon can use. Keep a custom practice-assist setting separate from the game’s real selector state. Update the label when changing weapons instead of leaving the previous gun’s mode in the HUD. A label that says automatic while the mechanism remains semi-automatic is a UI bug, even if the input script repeats presses.

Release checks

  • Tap and hold at low and high frame rates.
  • Open and close a menu while holding the input; release state must recover.
  • Switch weapons with the trigger held and confirm no queued action fires on the new gun.
  • Remove the mod and verify the normal selector and safety behaviour.
