Movement interpolation

Render remote movement smoothly without confusing smoothing with authority or prediction.

1. Start from correct snapshots

Record received position, orientation, receipt time and any sender timestamp under the correct session/world identity. Validate finite values and reject stale/out-of-order generations. Interpolation cannot repair a pose belonging to the wrong player or a previous range.

First prove the remote actor follows the correct target with direct samples. Then add smoothing and compare the same movement sequence; otherwise two bugs can mask each other.

2. Render slightly behind the latest data

Keep a small bounded history and sample an earlier render time so two surrounding snapshots are usually available. This trades some display delay for stability. The chosen delay should be a measured policy, not a magic number promised for every connection.

local function between(a, b, t)
    local duration = b.time - a.time
    if duration <= 0 then return nil end
    local alpha = math.max(0, math.min(1, (t - a.time) / duration))
    return {
        X = a.position.X + (b.position.X-a.position.X) * alpha,
        Y = a.position.Y + (b.position.Y-a.position.Y) * alpha,
        Z = a.position.Z + (b.position.Z-a.position.Z) * alpha
    }
end

3. Handle orientation separately

Yaw wraps at the angular boundary. Use the short-arc calculation from Vectors, rotations & spaces rather than averaging 179 and -179 into zero. General skeletal or full 3D orientation needs its own representation and tested interpolation.

For proxy walking/aiming, keep the displayed pose separate from authoritative player movement. A cosmetic character model should not move the real local pawn as part of smoothing.

4. Bound extrapolation

If the render time extends beyond your latest sample, a short velocity extrapolation can hide a gap. Cap its duration and velocity, then hold or indicate stale data rather than letting a proxy fly forever.

The local buffer used bounded history, a teleport threshold and capped extrapolation. Its numerical defaults were chosen for that implementation. They are not evidence of an optimal universal setting for every weapon, map or internet route.

5. Reset on discontinuities

A teleport, world change, backwards clock or restarted sender stream should clear the interpolation history. Interpolating across a teleport can sweep a character through the entire scene, and reusing a previous world’s clock can stall updates.

Do not calculate velocity from equal timestamps or a non-positive interval. Repeated stationary samples may be skipped deliberately, but ensure a real state change still reaches the visual model.

6. Measure jitter and visible delay

Log sample intervals, buffer age and stale periods separately from average ping. A low average ping does not guarantee evenly spaced samples. Increasing the buffer can smooth motion while making it visibly lag farther behind; show that trade-off in tests.

A useful test path includes standing, walking, sharp turns, aim changes, a pause in updates, teleport and reconnect. Compare both screens in a real session after the pure buffer tests pass.
