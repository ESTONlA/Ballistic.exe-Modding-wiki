HUDs, markers & nameplates

Design local overlays and world labels with clear identity, lifetime and presentation rules.

1. Choose screen HUD or world text

A screen-space HUD is appropriate for session status and local controls. A world-space nameplate follows an actor and needs a position, orientation and visibility policy. Avoid turning every label into the same kind of widget merely because one creation example is convenient.

Keep the displayed name separate from the stable player/session identity. A renamed or duplicate display name must not change who owns a score or remote gun.

2. Create a label with deliberate ownership

The local nameplate implementation spawned TextRenderActor, disabled collision and replication for its cosmetic proxy, configured the text component, and updated its transform relative to the player/camera. This was a mod-owned visual actor, not a new authoritative player pawn.

Track the label for cleanup and recreate it for the current world if needed. Do not keep an old-world text actor in a global player record after travel.

3. Choose position and facing

Use a known offset above the relevant actor, and orient toward the current camera where appropriate. A proxy body, real pawn and text label may have different root origins; inspect their actual transforms before choosing the offset.

Distance labels need a documented world-unit conversion. The local marker display divided its measured world distance by 100 for metres in that setup. Confirm scale with a known reference rather than applying that factor blindly to imported geometry.

4. Validate names as display text

Remove control characters, keep a bounded UTF-8-safe length and avoid interpreting markup-like input. A plain display name is not code or a file path. See Chat, names & text validation for the shared text problem.

Do not replace an unavailable player name with a nil concatenation that crashes every render update. Use a clearly defined fallback while preserving the internal identity.

5. Avoid redundant HUD writes

Cache successfully applied text, visibility and enabled state within the current widget tree. Update only when the desired value changes. If a setter fails, keep the entry retryable rather than marking a value as successfully displayed.

On menu rebuild, invalidate the cache because the old widget objects no longer describe the new tree. A global text cache detached from widget identity can leave new labels blank.

Verify the presentation

  • Labels follow the intended actor through movement and aim.
  • Two players with similar names remain distinct internally.
  • Long/Unicode names fit or truncate safely.
  • Close-range hiding, distance display and away state follow a defined policy.
  • Opening the local menu does not leave a duplicate overlay visible unintentionally.
  • Travel, disconnect and feature close remove the correct labels.

Projection into screen space is another transform stage; verify the current camera and the actual projection binding before converting world positions into canvas coordinates.
