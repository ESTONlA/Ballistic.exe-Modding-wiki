Shots & ballistics

A fired shot, a projectile impact and a valid target hit are separate events.

The shot pipeline

EventWhat it tells you
A_WeaponBase_C:ProcessBulletFiredWeapon firing event with cartridge, barrel and created bullet information.
C_BulletBase:RegisterHitA bullet reported impact information.
TargetBase_C:HitTarget hit path with projectile attribution in the inspected signature.
TargetBase_C:OnHitTarget reports validity, energy, velocity and bonus-related flags.

A projectile can strike non-target geometry. A target callback can be invalid. A shot counter and a scoring system should not increment from the same undifferentiated “hit” event.

Observe firing

Once the Blueprint function is loaded, a read-only hook can establish when it runs:

local path = "/Game/BlueprintLogic/Weapons/A_WeaponBase.A_WeaponBase_C:ProcessBulletFired"

-- Register once, after StaticFindObject(path) is valid.
RegisterHook(path, function(context)
    local gun = context:get()
    if gun and gun:IsValid() then
        print("[MyMod] Fired: " .. gun:GetFullName() .. "\n")
    end
end)

Observed shot arguments

After the context, the inspected firing signature has Cartridge, bullet and gas recoil forces, recoil location/direction, Barrel, powder amount, exit pressure, powder type and a Bullet array. Read the exact signature and unwrap parameters according to their type before using them.

Do not assume one event always produces exactly one bullet actor. Keep a shot ID and map each resulting projectile to it.

Impacts, energy and units

The target’s OnHit signature contains HitEnergy and HitVelocity, but a field name alone does not establish the units or all conversions used by the game. Record the raw values and compare controlled shots before labelling them in an overlay.

Don’t replace the game’s trajectory with a camera ray and call it the actual bullet path. A straight line can be useful as a cosmetic tracer, but it does not reproduce drop, penetration or ricochets.

What is not documented here

This guide maps events, not the complete internal ballistics model. Cartridge construction, powder curves, drag coefficients, penetration materials and every ammunition unlock rule still need dedicated research.

For score handling, continue to Hits & scoring.

Walkthrough: connect a shot to an impact

1. Start with one slow, controlled shot

Choose a gun and cartridge, keep the target distance fixed and fire once. Log a firing-event count and the weapon identity. Confirm a single trigger produces the expected firing callbacks before adding an impact counter.

Do not use a rapid-fire sequence to discover attribution. Several projectiles in flight make “the latest shot” an unreliable shortcut immediately.

2. Read the firing signature

Observed parameterMeaning to investigate
CartridgeThe cartridge object associated with the firing event.
BulletRecoilForce / GasRecoilForceTwo recoil-force inputs; not a substitute for muzzle velocity.
RecoilLocation / RecoilDirectionLocation and direction inputs for recoil processing.
BarrelThe firing barrel object.
PowderAmount / ExitPressure / PowderTypeAmmunition-related inputs with build-specific interpretation.
BulletArray of resulting projectile references.

Keep raw values and reflected types in a research note. Do not infer units, valid ranges or a complete ballistic formula from these labels.

3. Assign a shot identity

Increment a local shot number at the firing event. Associate every resulting bullet reference with that number and a timestamp. One shot can produce several projectile actors; a bullet’s runtime address is useful only inside the current process/world lifetime.

For a network message, send an explicit shot ID and session/round context. Never send a local address and expect the other process to have an object at that address.

4. Observe impacts separately

RegisterHit reports bullet impact information. Use the bullet-to-shot mapping to identify which shot produced it. A wall impact can matter for a tracer or replay without being a scoring target hit. Penetration or multiple contacts also make “one impact equals one shot” a weak assumption.

5. Observe the target decision

Read the target’s valid-hit decision and attribution before awarding a custom score. A target can report a contact that is invalid for scoring, has already been spent, or belongs to a different player/round.

Preserve the game’s own progression path. Cosmetic replication should not blindly replay a reward-granting callback.

Use a fixed distance and change one ammunition or barrel variable at a time. If two values differ, first check that they came from the same event and coordinate/time basis.

Cosmetic effects and real trajectories

A short-lived muzzle flash, sound or straight tracer can communicate that a friend fired. It does not establish the actual projectile’s full path. Keep effect lifetime bounded and clean up the actors/components your effect owns.

To document drop, penetration or ricochet accurately, gather projectile/impact samples and the game’s relevant configuration. This wiki currently maps useful entry points and the investigation method; it does not claim those internal systems have all been reconstructed.

What was checked

Firing and impact hooks resolved in local range checks; native target hit callbacks were also exercised. No full trajectory or ammunition-physics replacement has been validated. The examples describe the local Windows demo setup. See Checking game updates before using them on another build.
