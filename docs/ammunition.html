Cartridges & projectiles

Inspect cartridge and projectile data without pretending the full ballistic model has been recovered.

1. Separate cartridge, chamber, barrel and projectile

The cartridge used by a firing event, the barrel it is chambered in and the created bullet actors are separate objects. A magazine’s inventory is another relationship. Read those identities before comparing a numeric ammunition field.

A shot event may create several projectiles. Keep the cartridge identity with the shot ID and map each created bullet back to that event. This preserves attribution when several rounds are in flight.

These names were found in the local dump. Presence is not proof that changing one updates every derived field, nor that every cartridge class uses it identically. Keep read-only schema research separate from a released ammunition editor.

3. Inspect the bullet schema

C_BulletBase exposes fields including MuzzleVelocity, BaseVelocity, DragCoefficient, SimulationStepTime, Tracer and several shot-context flags. It also has a reflected CurrentEnergyInJoules function in the inspected dump. Its inspected signature includes a SurfaceType enum input, so do not assume a zero-argument raw-energy call. That function is an investigation point; it was not freshly exercised by this documentation pass.

Do not infer all units from a convenient variable name. The familiar kinetic-energy equation can be a cross-check only after the mass and velocity representations are known. It is not a replacement for the game’s pressure, drag, penetration or heat behaviour.

4. Make a controlled comparison

  • Choose one known weapon, barrel and cartridge.
  • Record identities and selected raw values before the shot.
  • Capture firing-event arguments and resulting projectile IDs.
  • Capture actual impacts and target validity separately.
  • Change one input or cartridge type, then repeat at the same setup.
  • Record what was measured versus merely found in a dump.

A different target distance, barrel or grip can invalidate a quick comparison. Keep the original configuration in the research note and avoid modifying the player’s permanent inventory for an early experiment.

5. Before building an ammunition editor

Determine where the editable template lives, which fields are inputs, which are computed outputs, how the game rebuilds a live cartridge and how purchases/selection persist. Directly assigning a projectile field after it is fired is a different feature from creating a valid selectable cartridge.

An editor also needs limits, rejected-input behaviour and a reversible save workflow. Do not call an undocumented field assignment a complete custom-ammunition pipeline.

What still needs dedicated research

Complete cartridge construction, pressure/propellant equations, drag/penetration tuning, every ammunition unlock rule and all persistence cases are not fully documented. This guide gives a typed starting surface and a repeatable investigation, not a claim of complete simulation coverage. Continue with shot/impact attribution and dump reading.
